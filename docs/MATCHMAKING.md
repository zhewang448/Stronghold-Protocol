# 同盟大厅与本服真人匹配

2026-10-26：维护者确认「个人匹配＋房主为已有同盟补人」，匹配后进入等待室，沿用准备和房主开始。
这是 `[ASSUMED]` 复刻便利功能，不改变官方战斗、卡池、组别或确定性规则。

## 入口与流程

- 首页仍保留独立模拟、同盟模拟、同盟大厅三张卡片，不增第四项。
- 同盟大厅直接提供版本、难度和「搜寻队友」；同盟模拟的快捷入口与创建页的大厅按钮均打开同一目录。默认不限版本，难度沿用上次选择。搜寻和取消留在操作栏，列表继续可刷新、加入与观战；关闭大厅仍可从首页状态按钮返回。
- 个人排队不提前建房，凑齐四人后用现有 `Lobby.create`、`Lobby.join` 建立同一等待室；排队较早者当房主。
- 公开四席原版房的房主可点「开始搜寻」补充散人；已有队友保持原房、原座位，不合并两个队伍。
- 只有主动搜寻的房间接收匹配玩家，普通公开房不会被自动填充。已有房间优先于散人新组房。
- 不自动开局、不自动补 AI、不替换已存在的 AI。新加入的真人仍需准备，房主用原「开始模拟」。
- 成功补入尚未满员的队友只进入等待室；只有满员才显示集结完成。
- 取消只退出队列，已经加入房间的玩家与房间保持不变；无超时自动重排，前端不每十秒反复入队。

## 首版兼容范围

同一服务器、兼容版本与难度条件，固定四席。版本可精确指定，也可选「不限版本」；难度可独立选「不限难度」，同一局仍只有一个实际难度。扩展 8/10/16/20 席、私密房、测试房、玩法插件、
自定义模式、版本投票及非默认便利规则房不参与；仍可通过同盟大厅、密钥或邀请手动组队。

匹配房使用默认便利设置、AI 后选，关闭观战接替 AI 和联防叠层。全局房间上限和每地址上限仍由原
创建接口裁决，失败回到 idle 并显示已有错误码，不假报成功。开启默认玩法插件的服无法用本首版自动建房。

房主或现有真人断线、离开、变更版本/难度/容量/隐私/规则、开局和销毁房间均终止该房搜寻。观战者
离开或断线不影响招募。散人断线立即移出队列，重连回到 idle，必须主动再次搜寻；服务器重启不恢复队列。

## 协议与实现

- C2S `match.queue { mode: 'coop', difficulty, version?, anyVersion?: boolean, anyDifficulty?: boolean, fillBots?: false, random?: false }`：入队幂等，改条件重新排队。
- C2S `match.cancel {}`：取消个人或自己主持房间的搜寻；其他成员无权取消整队。
- S2C `match.state { status, version?, anyVersion?, anyDifficulty?, difficulty?, startedAt?, target?, matched?, roomCode?, error? }`：服务器权威状态。
- S2C `match.found { roomCode, version, difficulty, full }`：已进入原房间通道，不包含自动开始指令。
- S2C `match.counts { byVersion, anyVersion, offered, features }`：精确版本和不限版本分别计数一次；`offered` 是服务器可用版本及难度。公开可见散人排队数，不是预计等待时间、不含房间人数。
- `room.state.matching` 仅搜寻期间存在，包含开始时间和目标人数；正常房 wire shape 不变。

`server/matchmaking.js` 维护内存队列，每秒清理与分配一次，新入队也立即尝试；同组按插入顺序，
散人保留同一 FIFO 队列，按实际候选版本检查兼容性。复用已有房间注册表、创建/加入/准备/开始、会话身份、重请求桶和社交隐身策略。
不另建账号、房间、计时器系统或战斗模拟。`match.queue` 受现有 heavy bucket 限流，取消仍可正常操作。

计数遵循主机 `social.counts`；隐身散人不计入公开数字，但自愿匹配成功后昵称会像普通加入一样被队友看到。
计数不含昵称、玩家 ID 或房间码。房主本人请求补人，房间公开码语义不变。

## 不限版本（2026-10-26）

`anyVersion` 缺省或 false 保留旧客户端精确匹配语义；true 时 `version` 是偏好，不再是硬约束。
不限版本只放宽玩法版本；未另选「不限难度」时难度不放宽。同一房间和一局仍只有一个实际版本和难度。

- 已有房主仍按房间版本和难度招募，不接受 `anyVersion: true`，不替房主切版。
- 同一队列中，不限版本散人可补入精确版本房；已有房优先，原成员、座位与房号保留。
- 散人分组先考虑精确请求的版本，按最早兼容者组成四人；不同精确版本不能由不限版本玩家串成一组。
- 四人均不限版本时，采用最早排队者偏好；不支持该难度或数据不可用时，按服务器注册表顺序选择可用版本。
- 没有可用版本支持所选条件时返回 `MATCH_UNSUPPORTED`，不降级难度、不创建错误版本房。
- 改版本偏好、精确/不限或难度时只重排本人；取消、断线、房间生命周期和隐身策略沿用首版。
- 计数隐私关闭时 `byVersion` / `anyVersion` 为 null；`offered` 仍提供非个人的服务器能力，供难度下拉框禁用不可选项。

本扩展是用户指定的 `[ASSUMED]` 便利。大厅复用现有目录轮询、加入/观战、焦点管理和等待室，不新增匹配页或第二套房间状态。

## 不限难度与预览修复（2026-10-27）

`anyDifficulty` 是独立可选布尔，缺省/false 保留精确难度。true 时 `difficulty` 为偏好而非硬约束；
两种不限可分别组合。房主补人仍固定已有版本/难度，拒绝任意一个不限字段为 true。

- 优先补兼容的主动招募房；新队满足全部精确版本、精确难度约束，不能用不限玩家拼接冲突条件。
- 全不限时先尝试最早排队者的版本和难度偏好，跳过不支持的组合，再按服务器版本注册顺序和
  `DIFFICULTIES` 顺序回退。明确指定的条件不会降级。
- 大厅难度新增「不限难度」，只放宽列表与队列，不把 any 写入原创建房间难度偏好。记忆不限选择使用
  `lobby.matchDifficulty`，原 `lobby.difficulty` 保持有效枚举。取消后条件保留。
- `match.state.anyDifficulty` 表示搜寻条件；`match.found.difficulty` 返回实际房间难度。计数中每人仅计一次，
  每个版本桶与 anyVersion 桶的 `anyDifficulty` 数字独立于 byDifficulty；隐身/counts 规则照旧。
- `match.counts.features` 显式声明 anyVersion / anyDifficulty 支持。旧服务器未声明时阻止不限请求，
  显示重启测试服务并刷新的提示，防止新页面配旧进程静默忽略布尔字段。
- 无兼容服务器版本/难度组合时返回新的 `MATCH_UNSUPPORTED` 与筛选提示，不再借用房间插件版本错误。
  没有在线房间本身不是错误：散人可正常排队，凑满四人再创建房间。

实测 3005 旧进程 PID 54012：零房间时，第一期偏好 + ABYSS + anyVersion true 返回 VERSION_UNSUPPORTED，
同样零房间下默认版本 NORMAL 成功。核对实例和空闲状态后，经本机原服务 API 平滑重启，
相同请求在新进程成功；精确第一期 + anyDifficulty true 也成功。记录在 ANY_DIFFICULTY_PREVIEW.json。
