# v0.3.1-extended.7 · 安全启动、更新验证与数据保护

基于上游 v0.3.1，上一正式扩展版为 v0.3.1-extended.6。本文件记录本版功能、使用方法与验证边界；正式附件和校验签名见 GitHub Releases。

## 更新内容

- 普通与公网启动统一检查 Node、依赖、素材及待应用更新；重复启动复用当前安装的服务，未知端口占用者不会被强杀。
- 启动器管理服务器和隧道各自的生命周期，控制台重启服务器时保留隧道；崩溃重试有上限，明确停服不再拉起。
- 签名增量包优先，缺失、不适用或验证失败则使用同版本完整包；回退旧版和修复素材使用完整包。
- 更新检查下载、展开和备份空间，验证候选应用、前端资源和 WebSocket，再验证正式服务；复制完成不误报成功。
- 只读探测失败恢复原程序和版本元数据；正式启动失败保留明确恢复状态，提供校验过的离线恢复路径。
- 控制台展示更新备份文件大小、状态和保留数，默认保留最近 2 个已验证恢复点，可设 1–20；保护最新好备份及未完成事务。
- 临时网址和长期未导出的个人数据获得非阻塞提醒，可延后、关闭；导出提醒记录不进入迁移包。
- 每次正式修补递增扩展版本，签名拒绝覆盖已封存的不同附件，并核对源码版本、工作区及已有标签。

## 使用与恢复

Windows 公网启动使用 `scripts/start-tunnel.bat`；本机停服使用 `scripts/stop-server.bat`，有活动局时需确认。
同一隧道进程可以跨服务器重启继续使用，整机或隧道进程重启仍可能更换临时网址。换域名前应导出个人数据。

升级前结束活动对局并备份 logs 与个人数据。恢复点记录前一版本变更路径，必须按安装顺序使用，不是任意版本全盘快照。
进入 `recovery-required` 后，先停止服务、启动窗口及外部守护器，再按状态文件中的命令离线恢复，重新启动后检查。
恢复不逆迁移用户数据，也不保证跨版本续接尚未结束的对局。详细步骤见 [部署说明](DEPLOY.md)。
