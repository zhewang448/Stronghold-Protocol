## 5. 共享渲染与性能方案

### 5.1 绘制与数据结构

内嵌视图采用Stardust结构：每个可见图片框一个2D canvas和独立骨架实例；一个共享的Pixi renderer将可见实例按尺寸分页绘制，再把相应区域复制到图片框。重用本库 `ensurePixi`、现有Spine加载缓存和资源解析器。

核心能力包含注册/释放视图、更新取景、标记dirty、可见性、播放状态、加载/首帧/失败状态。单张完整预览沿用按需创建的独立实例，同一时刻只保留当前预览。共享的是绘制资源，角色动画和取景仍各自独立。

素材身份至少包含角色/外观、动态资源URL或内容身份，避免不同版本或外观插件覆盖后复用旧骨架。支持经过验证的`.skel`和JSON骨架；读取atlas全部纹理页，尊重PMA。缺bounds时先摆待机姿势再测量，不能用未初始化的setup pose裁切。

### 5.2 首版性能策略

以下是本项目的工程默认值，不是官方玩法规则，实施时写入说明并用性能结果复核：

| 项目 | 首版约定 |
| --- | --- |
| 自动播放 | 本地“动态立绘”总偏好支持自动/静态；已有明确关闭值保持关闭；自动仅在素材有效且视图可见时播放 |
| 帧率 | 动态UI桌面最高30 FPS、粗指针最高24 FPS；用户现有正数FPS上限更低时取更低值；不改变战斗模拟频率 |
| 像素密度 | 有效DPR初始上限1.5；缩略图可采用更低像素预算；大图优先保清晰度 |
| 页面后台 | 明确停止调度；恢复时重置时钟，避免动画一次跳过后台时长 |
| 减少动态效果 | 自动内嵌视图显示静态；大图可由用户明确点击播放，关闭后回到原偏好 |
| 离屏 | IntersectionObserver决定激活，可保留来源的64px预载边界；边界外不保留活跃动画实例 |
| 静止 | 所有实例暂停且无dirty任务时，不持续请求无效帧 |
| 释放 | 最后一个视图离开后，短暂空闲再释放共享renderer，初值5秒；取消旧加载的晚到回调，归还骨架引用 |
| 失败 | 保留静态图；单项失败不拖累其他视图；重试有界；缺素材不反复创建实例 |

共享画布分辨率受GPU纹理/renderbuffer/viewport上限限制，来源的4096页上限可保留。需要对单视图超大像素尺寸做等比例降采样，不能只裁掉超出页的部分。画布尺寸变化、DPR变化、容器滚动和取景变化必须触发正确重绘。

目标是在正常设备上让可见动态位置按参考界面播放。若性能预算不足，应优先保留正在预览、当前选中和本人席位，降低次要缩略图的分辨率/刷新率；任何数量或自适应上限都必须测量后说明，不能无提示地把所有内容关掉。

共享方案每帧仍有画布区域复制成本，不预先宣称最快。先按相同立绘、相同像素尺寸测量1/4/12/40个可见实例，再决定是否需要更复杂的统一覆盖画布；第一阶段不为此整体更换渲染库。

### 5.3 单选控件规范

新增自动/静态等分段选项使用统一组语义和可访问名称。Tab只进入当前选中项，方向键移动焦点并更新选择，Tab离开整组；Home/End到首尾，跳过禁用项；选中状态与键盘焦点框分别呈现。按组方向支持左右或上下，不能干扰中文输入法。此要求可先落实到本次新增控件，再独立推广到旧设置。

## 7. 素材准备与发布链路

普通头像/半身像/技能图标可参考 [ArknightsGameResource](https://github.com/yuanyan3060/ArknightsGameResource)，战斗骨架参考 [ArknightsResource](https://github.com/fexli/ArknightsResource)，静态大立绘核对PRTS。塔露拉战斗资源目录为 [char_4247_oxi](https://github.com/fexli/ArknightsResource/tree/main/spine/char_4247_oxi/char_4247_oxi)。

动态大立绘通过参考分支的素材声明、实际骨架/atlas/纹理页、前景/背景层与bounds核验后安装。缺少动态记录的角色保持静态，不用战斗小人的骨架冒充大立绘，也不承诺每名新干员都具备动态外观。

下载器、安装器、清单生成器和UI必须形成一条可重复的链路：

1. 明确角色/外观→公开来源及原始文件身份。
2. 下载到工作树独立素材目录；保留哈希、文件类型和尺寸。
3. atlas规范化、骨架解析、附件区域、动画角色及命中事件验证。
4. 清单通过生成器登记；已有安装记录保留，失败不把成功条目静默丢掉。
5. 外观加载器/缓存/插件overlay与UI读取同一份动态记录。
6. 资源管理能识别动态文件并按既有必备/可选策略下载或导入导出，处理离线与缺素材回退。
7. 校验完整包、精简包、增量更新包和素材分包的来源依赖与路径，保留署名。代码进Git，游戏图片、骨架、音频不进Git。

不要直接在两个工作树间以可写链接共享atlas、清单或素材目录。本库工具会规范化部分文件，新工作树使用选择性复制/独立下载；源目录既有游戏资源保持原状。

## 9. 验收矩阵与必要检查

### 9.1 界面、生命周期与性能

- 尺寸：1920×1080、1440×900、844×390、640×360；触屏仿真与鼠标分别验证。实体手机未测时明确说明。
- 文字小/中/大/特大、布局缩放75%仅小字号、五种界面语言；截图对比静态与动态的构图、首帧切换及弹窗边界。
- 1/4/12/40视图，滚动离屏、进入/关闭预览、快速切皮肤/角色/版本、进出房间、页面隐藏/恢复、DPR与尺寸变化；至少一组真实立绘，不能只有合成骨架。
- 缺骨架/atlas/纹理页、超时、无bounds、JSON骨架、多页贴图、PMA差异和上下文丢失/恢复；始终有稳定静态回退。
- 默认嵌入绘制同时存活的WebGL上下文应为1，完整预览最多另1个；战场已有上下文单独计数。renderer回收重建后累计创建数可以上升，不能把累计值当作并发泄漏。
- 保存同一机器/浏览器/GPU/视口/素材组合下的frame-time p50/p95、实际绘制帧率、活跃视图/上下文、内存趋势和切换耗时。完整遍历退出后实例/引用回收，重复循环不能持续增长。
- 暂停/后台/离屏不做空转；用户点击和滚动无明显新增阻滞。先使用24/30 FPS上限测量，达不到再据数据调整，不把“语法通过”写成性能通过。
- Tab/方向键/Home/End、Esc、焦点恢复、触屏点击/长按/拖动，确保动画层没有吞掉操作。

### 9.2 游戏机制与回归

- 新干员3技能×普通/精锐×5/6阶、天赋、职业、正式模组；攻击范围、时序与伤害归属采用当前结算API。
- 自选名额、持有和预设导入导出、版本切换；已有四位及七名联动可选状态保持正确。
- 单人、4人、至少一组20人分组/联防；同名新干员来自不同玩家；历史版本和插件房有明确支持/回退范围。
- 浏览器/Node同一BattleSpec摘要一致，回档与回放不丢新角色状态；旧记录不因缺少新显示字段而崩溃。
- 动态UI阶段的golden应保持不动；新干员阶段的预期变化逐场景解释。不能从参考仓库覆盖golden文件。
