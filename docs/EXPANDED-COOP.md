# 扩展联机实验分支

本分支由维护者于 2026-10-21 授权试验多人扩容。它是社区扩展，不是官方玩法或上游发布版。

2026-10-22，维护者授权合并到本地 main。普通启动入口也可设置房间容量；下列 3188 / 3288 启动器继续用于独立测试，
合并本身不重启现有服务，不创建 Release，也不推送远端。

## 当前规则

- 同盟房默认仍为四人，房主可在等待室设置中选择 **4 / 8 / 10 / 16 / 20**。不能缩小到已占用的最高座位以下，开局后不能改变容量。单人模式保持一个座位。
- 真正的参战人数取开局占用座位，包含 AI、不含空位和观战者。四个人进入二十人容量的房间，仍按四人对局处理。
- 六人起使用固定卡池分组：六人 3+3、八人 4+4、二十人 4+4+4+4+4；其余分组表在 `shared/playerCapacity.js`。成员退出或淘汰后不重新分组。
- 各组共享干员 / 装备池独立。三、四人组保留完整基准库存，五人组扩大为 1.25 倍；跨组赠送使用接收者所在组的库存。
- 策略与机变按组并行、组内依次选择，机变每组六个选项，界面标记 A–E 组。请求携带可选的阶段与组身份，拒绝过期请求及其他组的选择。
- 联防每场仍最多两名助手，最多轮数等于开局固定组数、上限五轮；包括后续漏怪结算及多数在线手动真人投票跳过后续联防。
- 首领战仍按两人分场，扩展共享血量和隐藏关门槛，不扩大棋盘。
- 开局参战人数超过四人的对局，首领战中途退出会同比缩减血池并移除退出者的隐藏关层数贡献；四人及以下保留开战时的血池和层数快照。
- 四人及以下保留原有 AI 最后选择开关及跳过行为。私人自选库存继续使用本分支 / 上游已有的联机翻倍规则，没有迁入供体 D028 的私人库存改动。
- 网络继续使用现有 JSON / state-delta 协商；未引入供体的紧凑 wire、素材缓存、公告平台或大厅运维功能。

## 本分支兼容

- 回档保存每个稳定 groupId 的干员池与装备债务；恢复后玩家仍引用原分组池。
- PREP 快照不保存已结束轮选的计时器回调；回档取消废弃时间线的计时器及测试模式挂起回调。
- 重启恢复保存房间容量及全部分组库存。
- 主机监视台按每页四席显示，切页卸载旧战斗 iframe，不同时开启二十个渲染器。
- 浏览器战绩及每回合玩家列表上限随 `MAX_SEATS` 扩展。

## 兼容性复查（2026-10-22）

- 联防的浏览器进度上报原来仍截取前四个漏怪来源，现保留全房间来源，避免后排玩家的实时剩余敌人数误显示为零。

- 只读插件的房间、局内和结算玩家列表保留最多二十人及空席位；继续过滤私人配置，并补全既有社交请求的只读边界识别。

## 第二轮兼容性复查（2026-10-22）

- 联防现场产生的分裂怪、召唤物原先可能被带入下一轮，丢失运行时来源标记后成为应扣血漏怪。现只让原先逃出的敌人进入后续轮次；仅剩运行时子怪时不再开启下一轮，沿用 §34.19 不额外计费的规则。
